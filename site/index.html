The HTTP client that keeps your requests in plain files

Postino is a fast, native API client. No account, no cloud, no telemetry. Every request is a small text file you can read, diff and commit next to your code.

Download Postino View on GitHub

For Linux, Windows and macOS

  • Native, not a browserWritten in Rust on gpui, the GPU accelerated UI framework behind the Zed editor.
  • Light on your machineNo bundled web engine, so it stays small in memory and quick on any computer.
  • Local firstNo sign in, no sync, no telemetry. Only the requests you send leave your computer.
  • Yours to keepOpen source under Apache-2.0, with a documented, open file format.
See it in action

From a file to a passing test

Open a request, send it and check its tests, then jump to another one with the command palette. All from plain files on your disk.

Plain files, with Git built in

One request, one file. Diffs you can actually review.

A collection is a folder and a request is a short, readable .postino file inside it, so a change to a request is the one line you changed. Review it and commit it without leaving Postino.

Source Control, next to your requests

See what changed since the last commit, request by request, and read each change side by side, unified, or grouped by part of the request. Pick what goes in, write the message and commit, or commit and push.

  • Stage a whole file or a single block of changes
  • Branches, push, pull and a log with its commit graph
  • Secrets live in a .local.env file, kept out of every commit by default
Features

Everything you need to work with HTTP APIs

A familiar layout, built for speed: collections on the left, the request on top, the response below.

Scripts and tests in JavaScript

Run a script before a request to sign it or build data, and after it to check the response and pass values on to the next one. Scripts run in a sandboxed QuickJS engine.

  • test() and expect() assertions, with results per request
  • Save a token from the login response into the environment
  • Console output captured next to the response

Environments you can see and edit

Open any environment from the Environments panel and edit its variables in a table. Each variable shows the file it lives in, so shared values stay in .env and secrets in a .local.env file that never reaches git.

  • Move a variable between the shared and the local file with one click
  • Secrets masked until you choose to show them
  • Values set by scripts during the session, shown next to the rest
Load testing

Load test your API without another tool

Point a load test at a request or a whole folder, with the same environments and scripts. Watch it live, set the goals it must meet, and dig into every request it made.

Live results, with goals

Choose virtual users, duration, ramp-up and think time, and see requests per second and latency second by second. Add thresholds and the run tells you whether it passed.

  • Requests per second, p50, p95, p99 and error rate, each compared with an earlier run
  • Goals on any of them, drawn on the chart and checked at the end
  • Drag over the chart to study one stretch of the run

Every latency, not an average

Every request of the run is kept. See how latency spreads, request by request, and how it moved since the last run on the same scale.

  • Latency distribution stacked by request, linear or logarithmic
  • Percentiles up to the maximum, and a curve of every percentile
  • Each request with its status, latency and virtual user, with filters and the errors grouped

Reports ready to share

Export a run, or only the window you selected, and attach it to a ticket or a pull request. Runs are saved next to your requests, so you can open any of them later.

  • A PDF report with charts, or the same report in Markdown
  • Every request as CSV, or the whole run as JSON
  • The summary copied as Markdown with Ctrl Shift C

  • {{uuid()}}

    Template functions

    Generate a UUID, a timestamp, a random value or a Base64 string inline, without writing a script.

    Import from Postman

    Bring your Postman collections and environment exports, and keep working with them as plain files.

    Keyboard first

    Jump to any request or action from the command palette, send with Ctrl Enter and switch environments with Ctrl 1 to 9.

  • curl · fetch · requests

    Turn any request into code

    Copy it as a curl command, a JavaScript fetch or a Python requests call, with every variable resolved.

    Light and dark themes, or follow your system, your choice of fonts and sizes, and four languages.
