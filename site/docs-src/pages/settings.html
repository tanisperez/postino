Settings

Open Settings with the gear in the title bar or Ctrl , (⌘ , on macOS). Changes apply immediately and are saved as you make them; there is no Save button.

Settings are grouped in five categories. Reset to defaults brings every setting back to its default value.

Requests

TLS

Use system certificates (on by default) verifies server certificates with the operating system's certificate store, like a browser does: the Windows certificate store, the macOS Keychain, or the system bundle on Linux (the SSL_CERT_FILE and SSL_CERT_DIR environment variables, when set). That store also has the certificate authorities your company installs, so internal APIs and networks that inspect TLS work without a warning. Turned off, Postino trusts only the Mozilla roots it bundles. On Linux the system bundle is read once, so restart Postino after installing a new CA.

Invalid certificates decides what happens when a server's certificate is self-signed, expired or issued for another host name:

OptionBehavior
Send with warning (default)The request is sent without verifying the certificate, and the response shows a warning that explains what was wrong. Handy for local servers with self-signed certificates, while still telling you about the problem.
RejectThe request fails with an error, like a browser would.
Don't verifyThe request is sent without verifying the certificate and without any warning.

A certificate error stops the TLS handshake before any request byte is written, so retrying without verification never sends a request twice.

Responses

Maximum size is the biggest response body Postino reads: 10, 20 (default), 50, 100 or 200 MB, where 1 MB is 1,000,000 bytes. A bigger response fails with an error that names the limit. A big response uses about 30 times its size in memory while it is shown, so raise the limit only as much as you need. In settings.toml you can set any value from 1 to 1000.

Git

The settings of the Git integration.

Git executable

Leave it on Auto-detect (default) to use the git found in your PATH, or pick a binary with Browse…; choosing Auto-detect in the list goes back to searching. Detect again looks for git again, for example after installing it. Below, Postino shows what it found, such as git version 2.47.1 · Postino needs 2.30 or later, or why git cannot be used: not found, the Xcode Command Line Tools are missing (macOS), the version is older than 2.30, or git failed to run. When git is not available, a How to install Git link opens Installing Git.

The branches you star in the branch menu are saved as git_favorite_branches in settings.toml, a list of names such as ["main", "origin/release"] shared by every repository. It has no row in the Settings window and is left out of the file when empty.

Commit author is read only. It shows the user.name and user.email that git config gives the open workspace's repository, or Not configured when there is no repository or no author. Change it with git config.

Advanced

Logging

Log level controls how much Postino writes to its log file: Off, Error, Warn, Info (default), Debug or Trace. Debug and Trace add detail to diagnose problems. The log file location is shown below the setting, with an Open folder button. Files are rotated every 5 MB and the last 10 are kept.

The POSTINO_LOG environment variable overrides the level at startup. See Command line and collecting a log.

Privacy

Logs never contain request or response bodies, variable values, query strings or the values of sensitive headers such as Authorization or Cookie.

About

Shows the version and links to the release notes. A development build (a version ending in -dev) also shows the short commit it was built from next to the version, such as 0.5.0-dev (9bb54cc). Under the version, Design system names the version of telaio, the library Postino's look and standard components come from; a click on telaio opens its repository. Include both versions when you report a visual bug. What else it shows depends on how Postino was installed:

  • macOS and Windows builds from the official installers have the in-app updater. Check for updates automatically (on by default) checks once, a few seconds after launch, and never polls in the background. Check now checks immediately. When an update has been downloaded and verified, Restart to update installs it. Restarting keeps your open tabs; if a tab has unsaved changes, Postino asks first.
  • The Windows portable zip checks too, but downloads nothing and does not show the download folder. When a newer version exists, a banner says so and its Download button opens the release page, where the new zip is. See Installation.
  • Linux copies installed without a package manager (the install script, the tarball, the AppImage) check too, but download nothing. When a newer version exists, a banner says so. For the install script its Copy command button copies the install command, which updates Postino when you run it again; for the tarball and the AppImage, Download opens the release page. See Installation.
  • Linux packages (apt, dnf, zypper, pacman) say that updates come from your package manager.
  • Other builds, such as one you compiled yourself, say that updates are not available in that build.

The privacy line states what Postino connects to on its own: nothing at all, or, in builds with the updater, only GitHub to check for updates. That check sends no identifiers.

The settings file

Settings are stored in settings.toml in Postino's configuration folder. The exact path is shown at the bottom of the Settings window, next to Saved to.

SystemPath
Linux~/.config/postino/settings.toml (or $XDG_CONFIG_HOME/postino/)
macOS~/Library/Application Support/postino/settings.toml
Windows%APPDATA%\postino\settings.toml

You can edit it by hand while Postino is closed. Keys you leave out take their default value, and an invalid value falls back to the default.

```toml title="settings.toml" language = "auto" # auto, en, es, gl, it theme = "system" # system, light, dark ui_font = "Geist" ui_font_size = 13.0 # 11 to 16 mono_font = "Geist Mono" mono_font_size = 12.5 # 10 to 18 json_indent = 2 # 2 or 4 invalid_tls_certificates = "warn" # warn, reject, accept system_tls_certificates = true # false: only the bundled Mozilla roots max_response_mb = 20 # 1 to 1000 log_level = "info" # off, error, warn, info, debug, trace check_updates = true # only used by builds with an updater show_welcome = true # show the welcome tab next to the last workspace # git_executable = "/usr/bin/git" # absent: auto-detect from PATH git_fetch_automatically = true # fetch when the window regains focus, every 5 minutes at most git_pull = "follow_config" # follow_config, merge, rebase git_commit_action = "commit" # commit, commit_and_push git_block_secrets = true # block commits that include a .local.env file git_confirm_discard = true # ask before discarding changes git_diff_mode = "split" # diff tab layout: split, unified or request, set from its toolbar git_favorite_branches = ["main"] # branches starred in the branch menu, absent when empty ```
