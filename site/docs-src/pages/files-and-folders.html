Files and folders

Postino keeps your work in your workspace and its own state in your user folders. Nothing is stored anywhere else, and nothing is sent anywhere.

In the workspace

These files belong to the project and are meant to be shared, except where noted.

PathContentsIn git
**/*.postinoOne request per file. See File format.Yes
environments/<name>.envShared variables of an environment.Yes
environments/<name>.local.envSecrets and personal overrides.No, add *.local.env to .gitignore
<collection>/.openapi.tomlWritten by an OpenAPI import: the source of the spec and what it generated, to update the collection later. Hidden in the sidebar.Yes
.postino/project.tomlThe workspace configuration, shared with everyone who uses the workspace. See Workspace configuration.Yes
.postino/runs/NNNN.jsonLoad test run history, one file per run: its configuration, thresholds and metrics.Your choice

.postino/import-report.mdThe report of the last Postman or Bruno import that had something to report.Your choice
.gitignoreWritten once, when Postino creates the workspace, together with .postino/project.toml. It ignores *.local.env, .postino/runs/ and .postino/import-report.md.Yes

Postino never writes anything else into the workspace: no settings, no cache, no lock files. It never edits the .gitignore of a folder you open.

Workspace configuration

.postino/project.toml holds the settings that belong to the workspace rather than to you, so they travel with it through git. It is a TOML file:

version = 1

[environments]
order = ["local", "dev", "staging", "prod"]

[environments.colors]
local = "teal"
  • The file is optional. A workspace without it works as usual, and opening a workspace never creates it. Postino writes it when it creates a workspace, and the first time you change something the file holds. Renaming or deleting an environment updates the file only if it exists.
  • Postino keeps the keys it does not know when it saves the file, and ignores values of the wrong type. A file that is not valid TOML is reported and never overwritten: fix it, or delete it to start again.
  • If your own .gitignore ignores the whole .postino/ folder, the file is not shared. Ignore .postino/runs/ and .postino/import-report.md instead, as the .gitignore of a new workspace does.

Load test runs

Each load test run is saved as two files in .postino/runs/, numbered with four digits:

  • NNNN.json is small. It holds the run number, when it started, the target, the configuration (virtual users, duration, ramp-up, think time, Stop on errors, Reuse connections and the number of requests, never their bodies or secrets), the thresholds the run was started with, whether it stopped early, the method and name of each request, and the final metrics: totals, percentiles, the series per second (requests per second, virtual users, p50, p90, p95 and p99), the latency histogram, the status counts, the per request statistics and an example of each kind of error.
  • NNNN.samples.csv.gz is the gzip of a CSV with one line per request the run made. Its header is elapsed_ms,vu,target,status,latency_us,size,error,url: the time since the start in milliseconds, the virtual user (from 0), the index of the request in the target, the status (the HTTP code, timeout or failed), the latency in microseconds, the size of the response in bytes, 1 if it counted as an error and 0 otherwise, and the URL. You can read it with any tool that handles gzip and CSV. Postino reads it only when you open the run's Requests or Errors tab, select a window or export, so listing runs stays fast. It grows with the number of requests of the run.

Runs saved by older versions of Postino have only the .json file. They still open, but without per request detail, see Run history. Deleting a .samples.csv.gz file does the same to a newer run, and deleting both files removes the run.

OAuth profiles

Each OAuth 2.0 profile is a table [oauth.<name>]. The name has only letters, digits, - and _. Every text value takes {{ }} variables. Postino writes only the keys that differ from their default, except grant, and pkce and redirect for the authorization code grant.

KeyValue
grantauthorization_code (default), client_credentials or password
auth_urlThe authorization URL, for authorization_code
token_urlThe token URL
client_id, client_secretThe client. Keep the secret in a .local.env variable
scopeThe scopes, separated by spaces
username, passwordFor password
pkcetrue (default) or false
redirectloopback (default), fixed or manual
redirect_urlThe URL of fixed and manual
client_authbasic (default) or body
token_inheader (default) or query
token_prefixThe scheme of the header, Bearer by default
token_paramThe query parameter, access_token by default
[oauth.<name>.token_params]Extra parameters of every token request
[oauth.<name>.auth_params]Extra parameters of the authorization URL

A missing or unknown grant reads as authorization_code. Keys Postino does not know are kept when it saves a profile.

On your system

Postino's own state lives in the standard folders of each system.

Configuration

SystemFolder
Linux~/.config/postino/ ($XDG_CONFIG_HOME/postino/)
macOS~/Library/Application Support/postino/
Windows%APPDATA%\postino\
FileContents
settings.tomlYour settings.
recent-workspaces.txtThe last ten workspaces you opened, one absolute path per line, most recent first.
last-environments.tomlThe active environment of each recent workspace, so it is selected again when you reopen it.
last-version.txtThe last stable version that ran, so the What's new tab opens once after an update. Delete it to see the tab again on the next start.
window.tomlThe size of the window and whether it was maximized, saved when it closes. Postino opens with them the next time, centered and fitted to the display. Delete it to go back to the default size.

Logs

SystemFolder
Linux~/.local/state/postino/ ($XDG_STATE_HOME/postino/)
macOS~/Library/Logs/Postino/
Windows%LOCALAPPDATA%\Postino\logs\

The current log is postino.log. It is rotated at 5 MB, and at most 10 files are kept. Settings, Advanced, Logging shows the path and has a button to open the folder.

Updates

On macOS and Windows, the updater downloads new versions to postino/updates/ inside the system cache folder (~/Library/Caches/ on macOS, %LOCALAPPDATA% on Windows) and verifies them before installing. Settings, About shows the exact path. Nothing is downloaded on Linux, nor by a portable Windows copy, which only reads the manifest.

Resetting Postino

To start from scratch, quit Postino and delete the configuration folder. Your workspaces are not affected. To also remove the logs, delete the logs folder.

Network

Postino connects to:

  • the servers of the requests you send, when you send them or run a load test;
  • on builds with the updater (macOS and Windows, and Linux copies installed without a package manager), and only if Check for updates automatically is on or you check by hand, GitHub, to read the latest release manifest and download an update (a portable Windows copy and Linux only read the manifest). No identifiers are sent.

There is no telemetry, no crash reporting and no account.
