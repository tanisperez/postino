Contributing

Postino is open source and lives on GitHub. Bug reports, ideas and feedback are the most useful contributions right now.

Reporting a bug

Open an issue with:

  • your system and the Postino version (Settings, About);
  • what you did, what you expected and what happened;
  • a request file that shows the problem, with secrets removed;
  • a debug log, see collecting a log.

Code contributions

Before you start

The terms for external code contributions are still being decided. Open an issue to discuss a change before working on a pull request.

Building and testing

See Build from source for the toolchain and system libraries. On Linux and macOS, the Makefile wraps the usual commands:

CommandWhat it does
make runBuilds and runs a debug build
make releaseBuilds an optimized binary
make testRuns every test of the workspace
make lintRuns Clippy
make formatFormats the code with rustfmt
make sample-serverStarts the local test server of the sample suite
make sampleStarts that server and opens the app on the sample suite workspace
make helpLists every target

The tests never touch the internet: HTTP tests run against a local server. The sample suite in samples/ has about 140 requests that exercise every feature, each with its own tests.

Project structure

Postino is a Cargo workspace of small crates, with the user interface kept thin:

CrateResponsibility
postino-coreThe domain model and {{ }} interpolation
postino-formatParsing and writing .postino and .env files, Postman import, code snippets
postino-workspaceReading and writing workspaces on disk
postino-scriptThe QuickJS script sandbox
postino-httpSending requests
postino-runnerThe pipeline: variables, scripts, interpolation, sending
postino-loadThe load test engine and run history
postino-updateThe in-app updater
postino-appThe gpui desktop application

Developer documentation

The documents for people working on Postino itself live in the repository:

  • Architecture: the crates, the pipeline and the reasons behind them.
  • Design system: colors, metrics, typography and layout.
  • Translations: how to add a string or a language.
  • Sample suite: the local test server and its requests.
  • gpui notes: pitfalls of the UI framework.
  • Releasing: how versions are built and published.
  • AGENTS.md: the project's rules, also read by AI coding agents.

Translations

The interface is available in English, Spanish, Galician and Italian. Strings live in crates/postino-app/locales/, one YAML file per area with every language side by side. The translation guide explains how to add a language.

This documentation

Each page is a plain HTML file in site/docs-src/pages/ of the repository. make docs wraps them in the shared layout and make site previews the result on http://localhost:8000. Every page has an Edit this page on GitHub link at the bottom that opens its source.
