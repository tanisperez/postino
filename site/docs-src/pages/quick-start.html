title: Quick start description: Open a workspace, create and send your first request, add an environment and a test in Postino. ---

Quick start

This tutorial takes about five minutes. You will open a folder as a workspace, send a request, move its base URL into an environment and check the response with a test.

1. Open a workspace

A workspace is any folder on your disk. A good place is a folder inside the repository of the API you are working on, for example api/requests/, so the requests travel with the code.

  1. Start Postino. The first time, the sidebar says Open a folder to get started.
  2. Click the workspace switcher, next to the Postino name at the top left of the title bar, choose Open folder… and pick a folder. It can be empty.
  3. Postino remembers it and opens it again the next time you start the app. The workspace switcher keeps the last ten folders you opened.

2. Create a request

  1. In the sidebar header, click the New request button. To create it inside a folder, right click the folder and choose New request.
  2. Type a name, for example list-users, and press Create. Postino writes list-users.postino into the folder and opens it in a tab.
  3. A new request starts as GET https://example.com. Replace the URL with an API you can reach, for example https://httpbin.org/get.

3. Send it

Click Send or press Ctrl Enter (⌘ Enter on macOS). The response pane shows the status, the time and the size, then the body. Switch between Pretty and Raw, look at the Headers tab, and use the search button to find text in a long body.

The tab shows a dot when it has unsaved changes. Press Ctrl S to save. Send always uses what is in the editor, saved or not.

Save before closing

Closing a request tab discards its unsaved changes without asking. Save first with Ctrl S.

4. Add an environment

Hard coding the host in every request makes it painful to switch between local, staging and production. Move it into a variable.

  1. Click Environments in the activity rail on the left (the second icon) and then New environment. Name it local and press Enter. Postino creates environments/local.env.
  2. The environment opens in a tab. Click Add variable, name it baseUrl and set its value to https://httpbin.org. Save with Ctrl S.
  3. Select local in the environment pill at the top right of the title bar, or press Ctrl 1.
  4. Back in your request, change the URL to {{baseUrl}}/get. The variable turns into a chip. An unknown variable shows in red, and clicking it opens the Define variable dialog.

Your workspace now looks like this:

```text title="my-api/" my-api/ ├── environments/ │ └── local.env └── list-users.postino ```

5. Add a test

Open the Post-response tab of the request and write:

```js test("status is 200", () => { expect(res.status).toBe(200); }); test("the response echoes the URL", () => { expect(res.json().url).toContain("/get"); }); ```

Send again. The Tests tab of the response shows 2/2 and the result of each test. A failed test does not stop the others.

6. Look at the file

Open list-users.postino in any text editor. It is short and readable:

```postino title="list-users.postino" GET {{baseUrl}}/get ::: post test("status is 200", () => { expect(res.status).toBe(200); }); test("the response echoes the URL", () => { expect(res.json().url).toContain("/get"); }); ```

Commit it with the rest of your code. Before you add secrets to an environment, add this line to your .gitignore so .local.env files never reach git:

```text title=".gitignore" *.local.env ```
