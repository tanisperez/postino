Code snippets

Turn the request you are working on into code: a curl command for a terminal or a bug report, a JavaScript fetch call or a Python requests call.

Generating a snippet

  1. Open the request.
  2. Click Code, at the right of the request editor's tabs.
  3. Pick cURL, fetch or Python, or press ← and →. The code is highlighted like the request editor's.
  4. Click Copy, or press Ctrl C (⌘ C on macOS). What is copied is exactly what the dialog shows, and the button says Copied for a moment. To copy only part of it, select it in the code first.

What goes into the snippet

The snippet is built from what is in the editor, saved or not, resolved against the active environment and the session variables:

  • Variables and template functions are replaced. A template function such as {{ uuid() }} is evaluated once for the snippet.
  • Enabled query parameters are appended to the URL, percent-encoded.
  • Only enabled headers are included, plus the automatic Content-Type for JSON, XML and form bodies.
  • The Auth tab is included as the request sends it: the Authorization header of Basic and Bearer, and the header or query parameter of an API key.
  • With OAuth 2.0, the snippet carries the token Postino holds for the active environment, in the header or query parameter of the profile. When there is none yet, or it has expired, the snippet shows <access token> in its place: send the request once to get a token. The Code dialog never signs in.
  • A form body is written field by field, in the style of each language.
  • Scripts are not run. Variables that only a pre-request script would set stay as {{name}} in the snippet, and so does any unknown variable.
Secrets are included

Because variables are resolved, the snippet contains the real values of tokens and passwords from your environment, including .local.env, and the OAuth 2.0 token of the session. Check it before pasting it into an issue or a chat.

From the command line

postino snippet <file> --lang curl|fetch|python prints the same code in a terminal, and postino import curl goes the other way, from a curl command to a request. See the command line reference.

Examples

For this request, with baseUrl set to https://api.example.com and token to abc123:

```postino title="users/create.postino" POST {{baseUrl}}/users Authorization: Bearer {{token}} ::: body json { "name": "Ada" } ```

cURL

One option per line. -X is left out for GET. Values are single quoted for a POSIX shell. A form body becomes one --data-urlencode per field.

```text curl \ -X POST \ 'https://api.example.com/users' \ -H 'Authorization: Bearer abc123' \ -H 'Content-Type: application/json' \ --data-raw '{ "name": "Ada" }' ```

JavaScript fetch

A JSON object or array becomes an object literal inside JSON.stringify(...), and a form body new URLSearchParams({...}). A body that is not valid JSON, for example because it still has a {{name}} marker, stays a single string.

```js await fetch("https://api.example.com/users", { method: "POST", headers: { "Authorization": "Bearer abc123", "Content-Type": "application/json", }, body: JSON.stringify({ name: "Ada" }), }); ```

Python requests

A JSON object or array becomes a dict or list passed as json, with True, False and None. A form body becomes a dict passed as data, and any other body a string passed as data.

```text import requests response = requests.request( "POST", "https://api.example.com/users", headers={ "Authorization": "Bearer abc123", "Content-Type": "application/json", }, json={"name": "Ada"}, ) ```
On Windows

The cURL snippet uses POSIX shell quoting. Run it in Git Bash or WSL, or adapt the quotes for PowerShell.
