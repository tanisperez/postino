Troubleshooting

Solutions to the problems people run into most often. If yours is not here, open an issue with a log attached.

A request shows as broken

The sidebar lists a file as name (broken) when it cannot be parsed. Open it in a text editor and check the parse errors. The usual causes:

  • A comment in the header block. # note right after the request line is read as a disabled header, and fails because it has no colon. Move notes to ::: docs.
  • A body without its marker: JSON right after the headers instead of under ::: body json.
  • A lowercase method: get instead of GET.
  • A misspelled or capitalized marker: ::: Body json, :::pre without the space.
  • Git conflict markers left in the file after a merge.

A variable is sent as {{name}}

The variable has no value in any layer, so it was sent literally. Check that:

  • the right environment is active in the title bar (not No environment);
  • the name matches exactly: variable names are case sensitive;
  • the variable is not only in a .local.env file of another environment;
  • a value set by a script came from a request you already sent in this session: session variables are cleared when Postino quits.

Click Define on the warning to add the variable to the active environment. See defining a variable from a request.

A folder does not show in the sidebar

The sidebar only lists folders that hold a request, somewhere inside them, or that are empty. A folder with other files and no .postino file is left out, and so are hidden folders, target, node_modules and folders Postino cannot read. See what the sidebar shows.

A folder is too large to open

Postino does not open a folder with more than 20,000 files and folders as a workspace, such as a home folder or the root of a large repository. Open the folder that holds your requests, for example api/requests/.

Changes made outside Postino do not show

Postino does not watch the workspace folder. After a git pull, a checkout or editing files in another editor, reopen the workspace from the workspace switcher. Tabs that are already open keep the content they had; close and reopen them.

I lost unsaved changes

Closing a request tab discards its unsaved changes without asking. A tab with a dot has unsaved changes; save with Ctrl S before closing it.

Certificate errors

With the default setting, an invalid certificate only produces a warning. If requests fail with a certificate error, the Invalid certificates setting is Reject. For a local server with a self-signed certificate, use Send with warning.

Postino trusts the usual public certificate authorities. It does not read custom CA certificates from your system store yet, so a server signed by a private company CA is treated as invalid.

The request times out

The timeout is 30 seconds for the whole exchange, including redirects. If the server is reachable from a browser or curl but not from Postino, check whether you need a proxy and set HTTPS_PROXY before starting Postino. See environment variables.

The response is larger than the limit

Bodies are capped at 20 MB by default. Raise Maximum size in Settings, Requests. Large bodies use a lot of memory while shown, roughly 30 times their size.

A script fails

  • Pre-request script failed: nothing was sent. The message has the JavaScript error. Look at the Console tab for your console.log() output.
  • Post-response script failed: the response is shown anyway. A common cause is res.json() on a body that is not JSON, such as an HTML error page. Check res.status first.
  • Timeouts and memory: a script that runs for more than 5 seconds or uses more than 32 MiB is stopped. Look for an infinite loop.
  • pm is not defined: the script was imported from Postman. See moving scripts from Postman.
  • req.body has no effect: the request has no body section. Pick a body type in the Body tab first.

The app does not open on macOS or Windows

Postino is not code signed yet. See first launch of an unsigned build.

The window is blank or slow on Linux

Postino draws with the GPU through Vulkan. Make sure the Vulkan driver for your graphics card is installed (for example mesa-vulkan-drivers on Debian and Ubuntu, vulkan-radeon or vulkan-intel on Arch). Start Postino from a terminal with POSTINO_LOG=debug to see what the graphics layer reports.

Collecting a log

  1. Open Settings, Advanced and set Log level to Debug, or start Postino with POSTINO_LOG=debug.
  2. Reproduce the problem.
  3. Click Open folder next to the log file path and attach postino.log to your issue.
  4. Set the level back to Info.

Logs leave out bodies, variable values, query strings and sensitive header values, but glance over the file before sharing it. The log folders are listed in Files and folders.
