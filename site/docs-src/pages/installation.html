Installation

Postino is a single desktop application with no account and no sign in. Download it for your system, or install it with your package manager to get updates with the rest of your software.

System requirements

Every file is published on the latest release page on GitHub. The download page links to the right one for each system.

Linux

Install script

On any distribution, one command installs the latest release for your user, with no sudo:

```shell $ curl -fsSL https://postino.tanis.codes/install.sh | bash ```

The script downloads the tarball of the latest release from GitHub, checks it against the release's SHA256SUMS and installs it under ~/.local: the program in ~/.local/bin/postino, and the menu entry, the .postino file type and the icons under ~/.local/share. It also writes the list of the files it installed to ~/.local/share/postino/installed-files, so updating and uninstalling touch exactly those. If ~/.local/bin is not on your PATH, it says so; the menu entry works either way.

Run the same command again to update to the latest release. It never installs a pre-release unless you ask for it with --version.

To pass options, put them after bash -s --:

```shell $ curl -fsSL https://postino.tanis.codes/install.sh | bash -s -- --uninstall ```
OptionWhat it does
--version X.Y.ZInstalls that release instead of the latest one.
--prefix DIRInstalls under DIR instead of ~/.local. A system folder such as /usr/local needs sudo bash. Pass the same --prefix to update or uninstall.
--uninstallRemoves the files the script installed. Your settings and logs stay, and the script prints where they are.
--purgeWith --uninstall, also deletes your settings and logs (see Files and folders). Your workspaces are never touched.
-h, --helpShows the options.

The script runs only on Linux x86_64 and needs curl, tar and sha256sum. Run it as your user: as root it asks for a --prefix, since installing into root's home would leave Postino where nobody finds it. If Postino is already installed in /usr/bin by a package manager, the script stops and asks you to remove that copy first, so you never have two copies that update differently. You can read the script before running it at postino.tanis.codes/install.sh.

Debian and Ubuntu (apt)

Add the signing key and the repository once, then install. Your usual apt upgrade keeps Postino up to date.

```shell $ sudo curl -fsSLo /etc/apt/keyrings/postino.asc https://postino.tanis.codes/postino.asc $ echo "deb [signed-by=/etc/apt/keyrings/postino.asc] https://postino.tanis.codes/apt stable main" \ | sudo tee /etc/apt/sources.list.d/postino.list $ sudo apt update && sudo apt install postino ```

Fedora and openSUSE (dnf, zypper)

Add the repository once, then install. The signing key is imported on the first install.

```shell # Fedora $ sudo curl -fsSLo /etc/yum.repos.d/postino.repo https://postino.tanis.codes/rpm/postino.repo $ sudo dnf install postino # openSUSE $ sudo zypper addrepo https://postino.tanis.codes/rpm/postino.repo $ sudo zypper install postino ```

Arch Linux (pacman)

Download postino-…-1-x86_64.pkg.tar.zst from the latest release and install it with pacman:

```shell $ sudo pacman -U postino-0.5.0-1-x86_64.pkg.tar.zst ```

There is no pacman repository yet, so pacman -Syu does not update Postino: install the package of the next release the same way. The install script is the alternative that updates with one command.

Tarball

The .tar.gz uses a /usr-like layout: bin/postino, plus the desktop entry, the MIME type and the icons under share/. Extract it anywhere and run bin/postino, or copy its contents under ~/.local to get the menu entry. A tarball install does not update itself: download new versions from the releases page.

The install script does all of this for you. From a clone of the repository, make install-latest runs the same script, with PREFIX as its --prefix.

What the Linux packages install

The .deb, .rpm and Arch packages install /usr/bin/postino, a desktop entry, the icons and a MIME type for .postino files. Your file manager then opens a .postino file with Postino on a double click.

They also recommend git, which the Git integration runs: apt and dnf install it along with Postino unless you turn recommended packages off, and the Arch package lists it as optional. Postino works without it, only the Source Control view needs it. On Windows and macOS, install it yourself if you want the Git integration, see Installing Git.

Windows

Download Postino-…-windows-x86_64-setup.exe and run it. The installer is per user: it installs into %LOCALAPPDATA%\Programs\Postino, needs no administrator rights, adds a Start menu shortcut (and an optional desktop shortcut) and associates .postino files with Postino.

With winget, from a terminal:

```shell > winget install Postino ```

Postino on Windows updates itself. winget upgrade also picks up new versions.

Portable zip

On a machine where running an installer is not allowed, download Postino-…-windows-x86_64-portable.zip instead. It holds postino.exe, the license and the notice. Unzip it anywhere you can run programs from, a folder in your profile or a USB drive, and double click postino.exe. There is nothing to install: no Start menu shortcut, no .postino file association and no entry in Apps. To remove it, delete the folder.

A portable copy still keeps its settings and logs in your user folders, like the installed one, so it is portable in the sense of not needing an installer, not of leaving no trace. It does not replace itself either: see Updates.

macOS

Download Postino-…-macos-arm64.dmg, open it and drag Postino to Applications. Or use Homebrew:

```shell $ brew install --cask tanisperez/postino/postino ```

Postino on macOS updates itself after the first install.

First launch of an unsigned build

Postino is not code signed yet, so your system asks once before opening it. Updates are not affected.

  • macOS: if macOS says it cannot verify the developer, open System Settings, Privacy and Security, and choose Open Anyway. Or run this once: ```shell $ xattr -dr com.apple.quarantine /Applications/Postino.app ```
  • Windows: if SmartScreen shows Windows protected your PC, choose More info and then Run anyway.

Updates

Installed fromHow it updates
apt, dnf, zypperWith your system updates. Postino never updates itself on Linux.
Arch packageInstall the package of the new release with sudo pacman -U.
Install scriptRun the install command again.
TarballDownload the new version from the releases page.
Windows installer, wingetIn-app updater, or winget upgrade.
Windows portable zipThe status bar tells you when a new version exists and opens the release page. Download the new zip and replace postino.exe.
macOS disk image, HomebrewIn-app updater.
Built from sourcePull and build again. Local builds have no updater.

The in-app updater checks once, a few seconds after launch, and never polls in the background. When a new version exists it downloads it, verifies its checksum and shows Update ready, restart in the status bar. Nothing is installed until you click it. You can turn the automatic check off in Settings, About, and check by hand from the command palette with Check for updates.

The updater trusts the same certificates as your system, like your browser does. On a company network that inspects secure connections, it works as long as the company certificate is installed in the system, which is usually done for you.

A portable Windows copy checks the same way but downloads nothing, because running the installer from it would add a second copy of Postino. Postino tells it apart from an installed one by the uninstaller (unins000.exe) that the installer leaves next to postino.exe. When a newer version exists, the status bar shows Update … available, download. Clicking it opens the release page, where the new zip is. Close Postino, unzip the new postino.exe over the old one and start it again. Nothing is restarted for you.

Uninstall

  • Debian and Ubuntu: sudo apt remove postino, then delete /etc/apt/sources.list.d/postino.list and /etc/apt/keyrings/postino.asc if you no longer want the repository.
  • Fedora: sudo dnf remove postino and delete /etc/yum.repos.d/postino.repo.
  • Arch Linux: sudo pacman -R postino.
  • Install script: curl -fsSL https://postino.tanis.codes/install.sh | bash -s -- --uninstall, adding --purge to also delete your settings and logs.
  • Windows: Settings, Apps, Postino, Uninstall. A portable copy is not listed there: delete its folder.
  • macOS: drag Postino from Applications to the Trash, or brew uninstall --cask postino.

Uninstalling never touches your workspaces. To remove your settings and logs as well, delete the folders listed in Files and folders.

Build from source

Postino builds with the stable Rust toolchain. Install Rust with rustup; the exact toolchain version is pinned in rust-toolchain.toml and installed on the first build. Then install the system dependencies:

  • Linux (Debian and Ubuntu package names): ```shell $ sudo apt install build-essential pkg-config cmake libfontconfig-dev libfreetype-dev \ libwayland-dev wayland-protocols libxkbcommon-dev libxkbcommon-x11-dev \ libx11-xcb-dev libxcb1-dev libvulkan-dev ```
  • macOS: Xcode with its command line tools.
  • Windows: the Visual Studio Build Tools with the "Desktop development with C++" workload.

Then build and run:

```shell $ git clone https://github.com/tanisperez/postino.git $ cd postino $ cargo run $ cargo build --release ```

The first command builds and starts a debug binary. The second builds an optimized binary in target/release/postino. On Linux, make install builds that optimized binary and installs it under ~/.local (or PREFIX) with the menu entry, the icons and the .postino file type, and make uninstall removes it. A full build of gpui takes a while and several GB of disk space. See Contributing for the development commands.
