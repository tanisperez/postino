# Postino website

The landing page, install page and user documentation served at <https://postino.tanis.codes>.
Plain HTML, CSS and JavaScript, no dependencies. The only build step generates the
documentation pages. How it is deployed: `docs/releasing.md`.

- `index.html`, `install.html`: the pages.
- `404.html`: the page GitHub Pages serves for any missing address. Its links are absolute.
- SEO: every page has a description, a canonical URL, Open Graph and Twitter tags with the card
  `img/og.png` (1200x630, rendered from `screenshots/og.html` by `screenshots/og-image.sh`). The
  home page has JSON-LD (`WebSite`, `SoftwareApplication`), and every docs page a `TechArticle`
  and its breadcrumb, written by `build.py`. `robots.txt`, `site.webmanifest` and `favicon.ico`
  sit at the root.
- `sitemap.xml` and `llms.txt` (a summary for language models, <https://llmstxt.org>): generated
  at the root by `make docs`, ignored by git. The sitemap lists the home, install and every docs
  page; `llms.txt` is `docs-src/llms.txt` with the docs pages and their descriptions filled in.
  Keep its facts in line with the README and the pages.
- `hello.json`: the response of the example request (`hello.postino`) that every new workspace
  gets, so its shape must not change: the example's test checks `app`.
- `docs-src/`: the sources of the user documentation. Not published.
  - `pages/*.html`: one file per page, with only its content: a `title:` and `description:`
    header, a `---` line, then HTML. Code goes in fenced blocks, `` ```lang title="file" ``,
    with `postino`, `js`, `json`, `env`, `toml`, `shell` or `text`, escaped by the build and
    highlighted by `js/docs.js`. Headings without an `id` get one from their text.
  - `template.html`: what every page shares: head, header, sidebar, footer and search dialog.
  - `build.py`: wraps every page in the template and writes `docs/`. The `NAV` list at its top
    sets the sidebar order, the breadcrumb and the Previous/Next links: add new pages there. It
    fails on a page missing from `NAV` or from `pages/`, a broken link or anchor between pages, a
    missing image and an em dash. Python 3 standard library only.
- `docs/`: generated by `make docs` (and by the website workflow), ignored by git. Never edit it.
- `css/docs.css`: the documentation layout (navigation, article, "On this page"), callouts,
  tables and the search dialog, on top of `style.css`.
- `js/docs.js`: search, the "On this page" list, heading anchors, copy buttons, syntax
  highlighting and the mobile menu. The search index is built in the browser the first time the
  search opens, by fetching every page linked from the sidebar, so it never goes stale. Without
  JavaScript the pages still read fine.
- `css/style.css`: every color, radius and font comes from the Postino design system
  (`docs/design-system.md`, the telaio crate's `src/palette.rs`). Each color token is a
  `light-dark()` pair, picked by `color-scheme`. Every screenshot is in the page twice, `.light`
  and `.dark`, and CSS shows the one for the active theme.
- `js/theme.js`: follows the system theme until the visitor picks one with the
  header button, keeps that choice in `localStorage` and sets `data-theme` on `<html>`. Without
  JavaScript the page still follows the system and the button is hidden.
- `fonts/`: Geist and Geist Mono (SIL OFL 1.1, `fonts/OFL.txt`), subset to Latin and converted to
  WOFF2 from the TTFs bundled by the telaio crate (`crates/telaio-ui/assets/fonts/`) with `pyftsubset`.
- `img/`: the logo (`packaging/icons/`) and the app screenshots, WebP only.
- `video/`: the demo video of the home page, as AV1 WebM, H.264 MP4 and a WebP poster. It plays
  muted and in a loop; `js/demo.js` stops it and shows the controls with reduced motion.
- `screenshots/`: the tooling that regenerates `img/*-light.webp` and `img/*-dark.webp`
  (`make screenshots`), the video (`make video`) and the Open Graph card (`og-image.sh`). It is
  not published.

Preview locally with `make site`, which builds the documentation and serves the site on
<http://localhost:8000>. After editing a page, run `make docs` and reload.

Deployed by `.github/workflows/website.yml` on every push to `main` that touches `site/`. The
workflow builds the documentation first, so a broken link stops the deploy.
