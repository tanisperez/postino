Importing from Postman

Bring your Postman collections and environments over and keep working with them as plain files. The import never overwrites anything and tells you exactly what it created and what it could not convert.

Exporting from Postman

  • A collection: in Postman, open the collection's menu, choose Export and pick Collection v2.1. You get a *.postman_collection.json file.
  • An environment: open the environment's menu and choose Export. You get a *.postman_environment.json file.

Importing

  1. Open the workspace you want to import into.
  2. In the sidebar header, open the Import menu and choose Postman collection… or Postman environment…. Both are also in the command palette.
  3. Pick the exported file.
  4. A summary lists the number of files created and any warnings. The new collection appears in the sidebar and the new environment in the environment picker.

Collections

The collection becomes a new folder at the root of the workspace, named after it. If a folder with that name exists, the new one gets a (2), (3) suffix, so nothing is ever overwritten. Postman folders become subfolders, and each request becomes a .postino file.

Postman Collection format v2.1 is supported. Files in format v2.0 are accepted when they parse the same way. Fields with no equivalent in Postino are ignored.

Names are made safe for every operating system: characters Windows does not allow become _, trailing dots and spaces are removed and names are cut to 120 characters. Two requests with the same name in one folder get a (2) suffix.

Scripts

Postman's pm.* API has no direct equivalent, so scripts are not translated. A request's scripts are copied in full but commented out, under a first line that says so:

GET {{baseUrl}}/users

::: post
// Imported from Postman. The pm.* API is not supported, adapt it.
// pm.test("Status code is 200", function () {
//     pm.response.to.have.status(200);
// });

Uncomment and adapt them with the translation table. Scripts set on the collection or a folder are not imported, since Postino scripts belong to one request; each one is reported:

folder "Users": a test script is not imported at the folder level, only per request

Environments

A Postman environment export becomes environments/<name>.env. Variables of type secret go to environments/<name>.local.env instead, so they stay out of git once you add *.local.env to your .gitignore.

After importing

  • Look at the warnings: they list every body, auth and script that needs your attention.
  • Activate the environment, send a few requests and compare with Postman.
  • Port the tests you care about to test() and expect().
  • Commit the result. From now on, a change to a request is a one line diff.
