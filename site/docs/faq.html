Docs / Help

Frequently asked questions

Short answers to the questions people ask before and after trying Postino.

Do I need an account?

No. There is no account, no sign in and no license key. Install it and open a folder.

Where are my requests stored?

In the folder you opened, as plain text files: one .postino file per request and one .env file per environment. Nothing is stored in a database or in the cloud. See Workspaces and collections.

How do I share requests with my team?

Commit the workspace folder to git, ideally in the repository of the API. Everyone who clones it has the same requests and environments, and changes are reviewed in pull requests. Secrets stay in .local.env files that each person keeps locally. See Working with git.

Does Postino send any data anywhere?

Only the requests you send. Builds for macOS and Windows also check GitHub for a new version once at startup, without any identifier, and you can turn that off. There is no telemetry and no crash reporting. See Files and folders.

Can I open my Postman collections?

Yes, import them: collections in format v2.1 (and v2.0) and environment exports. Requests, folders, headers, bodies, auth headers and variables are converted. Scripts are copied but commented out, because Postman's pm.* API is different. See Importing from Postman.

Can I use .http files from my editor?

No. The .postino format was inspired by .http files, but it is not compatible with them: sections such as ::: body json and ::: post have no equivalent there. Converting one by hand is quick, since both are plain text.

Is the file format stable?

It is documented in full in the file format reference, and Postino's test suite checks that every file reads and writes back byte for byte. It is designed to stay readable without Postino.

Which JavaScript features can scripts use?

Standard modern JavaScript on the QuickJS engine, plus the Postino globals (req, res, vars, env, test, expect, console, util). There is no network, file system, timers, modules or crypto. See the Script API.

Can a script send another request?

No. Run the requests one after the other and pass values between them with env.set(). For a sequence that runs many times, put the requests in a folder and load test it: each virtual user runs them in order.

Does Postino support GraphQL, WebSockets, gRPC or multipart uploads?

Not yet. Postino sends HTTP requests with JSON, XML, text or URL-encoded form bodies. A GraphQL query can be sent as a JSON body to the GraphQL endpoint. Multipart form data, file uploads, WebSockets and gRPC are not supported.

Is there an OAuth 2.0 helper?

Not yet. Get a token with a request to the token endpoint (a ::: body form with grant_type, client_id and client_secret), save it with env.set() in the post-response script and send it as Authorization: Bearer {{token}}.

Can I run my requests in CI?

Not yet: Postino is a desktop app and has no headless runner.

Which languages does the interface speak?

English, Spanish, Galician and Italian. By default it follows your system language and falls back to English. Change it in Settings.

Is it free?

Yes. Postino is open source under the Apache License 2.0, free for personal and commercial use.

How can I help?

Report bugs, suggest features and share how you use it on GitHub. See Contributing.

Found a mistake? Edit this page on GitHub or open an issue.
