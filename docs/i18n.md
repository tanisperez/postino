# Translations

How the UI is translated, the terms to use in each language, and how to add a string or a
language. The short version for agents is in `AGENTS.md`, Translations.

Languages: English (`en`, the source and the fallback), Spanish (`es`), Galician (`gl`) and
Italian (`it`).

## Decisions

| Topic | Decision |
| --- | --- |
| Library | [`rust-i18n`](https://crates.io/crates/rust-i18n) 4. `gpui-component` already uses it for its own strings (`i18n!("locales", fallback = "en")`). Translations are embedded in the binary at compile time, lookups are a hash map read, and `rust_i18n::set_locale` is process wide, so one call switches both Postino's strings and `gpui-component`'s (calendar, input context menu, ...). |
| Why not Fluent | Fluent handles complex plurals and gender, but it would be a second i18n system next to the one `gpui-component` already ships, with new crates and a runtime loader. The four languages only need "one" and "other" plurals, which a two-key convention covers. |
| OS language | [`sys-locale`](https://crates.io/crates/sys-locale). `get_locales()` returns the user's preferred languages in order (on Linux it reads `LANGUAGE`, `LC_ALL`, `LC_MESSAGES` and `LANG`; on macOS and Windows the system preference list). The first one whose primary language subtag is supported wins, and none matching means English. |
| Regions | Variants map to the base language (`es-MX`, `es_ES.UTF-8`, `it-CH`, `gl-ES`). |
| Setting | `language = "auto" \| "en" \| "es" \| "gl" \| "it"` in `settings.toml`, default `auto`. In Settings, Appearance, the first section ("Language"). Options are written in their own language (English, Español, Galego, Italiano). The first one is "Automatic (System)" translated, plus the detected language in parentheses. |
| Applying a change | Live, no restart. `rust_i18n::set_locale`, then every view that caches a translated string outside `render` re-applies it (`AppView::relocalize`), then `cx.refresh_windows()`. |
| Numbers | Localized with CLDR data through [`icu_decimal`](https://crates.io/crates/icu_decimal) 2: `1,234.5` in English, `1234,5` and `12.345,5` in Spanish (CLDR minimum grouping 2), the CLDR rules for Galician and Italian. Unit symbols stay as they are. |

## Files and keys

- One YAML file per area under `crates/postino-app/locales/`: `common`, `settings`, `request`,
  `response`, `shell`, `load_test`, `environments`, `navigation`, `shortcuts`, `update`. Parallel work on different areas never edits the
  same file.
- Format `_version: 2` (the one `gpui-component` uses): every key lists its four translations
  together, so adding a key means writing all languages in one place.
- Keys are dotted, area first, lowercase snake case: `settings.appearance.theme_label`,
  `request.tab.headers`. Strings repeated across areas (Cancel, Save, Close, Copy) live under
  `common.`.
- Plurals are two keys, `<key>.one` and `<key>.other`, read with `state::locale::plural(key,
  count)`, which passes `count` as an argument.
- Arguments use `%{name}` in the YAML and `t!("key", name = value)` in code.

## In code

- `main.rs` has `rust_i18n::i18n!("locales", fallback = "en");` at the crate root, so `t!` works
  in every module of `postino-app`.
- `state/locale.rs` is plain Rust with unit tests: `Language`, `LanguageChoice`,
  `match_language(tag)`, `detect(preferred)`, `resolve(choice)`, `apply(language)` and `plural`.
- In views, `t!("request.tab.headers")` directly in the element tree. It returns a
  `Cow<'static, str>`; wrap it with `SharedString::from(...)` where an API needs it.
- State functions that return labels build them with `t!` at call time and return `SharedString`
  or `String`. Never store a translated string in state that outlives a render, except where an
  API forces it.
- **Cached strings:** `InputState` placeholders are set once at construction. A view that owns
  inputs has a `relocalize(&mut self, window, cx)` method that sets them again, and
  `AppView::relocalize` forwards to its children. Lists built once (command palette items,
  menus) are built when they open, so they pick up the current language.
- **Performance:** a `t!` lookup per element per render is fine. Do not translate inside loops
  over the rows of a body or a response.
- **Numbers shown to the user** go through `state::number` (`format_integer`, `format_decimal`,
  `format_signed_decimal`, `icu_decimal`). The formatter for the active language is built once
  and cached, rebuilt only when the language changes. Never use it in logs, snippets, the run
  history JSON, or number inputs the user types in (they must keep parsing).

## What is translated

Every user visible string produced by `postino-app`: labels, buttons, tabs, menus, tooltips,
placeholders, empty states, dialog titles and text, inline messages built by the app, command
palette actions, the status bar and the load test dashboard.

Not translated:

- Log messages: they are for bug reports and stay in English.
- Errors produced by the library crates (parse errors, HTTP and script errors, test names and
  messages from user scripts). They are shown verbatim, inside a translated frame where the app
  adds one ("Could not load the file: {error}").
- HTTP vocabulary that is a literal value: method names, header names, status reason phrases,
  `JSON`, `XML`, MIME types, `.postino` keywords.
- Keyboard shortcut labels (`Ctrl`, `Cmd`).
- The `POSTINO_OPEN=components` debug gallery.

## Tests

- The locale is process wide and `cargo test` runs tests in parallel, so **no test may call
  `rust_i18n::set_locale`**. A test that needs a language uses `t!("key", locale = "es")`.
- `state/locale.rs` tests check that every key has a non-empty value in all four languages, that
  every `%{arg}` placeholder of the English text appears in each translation and no extra ones,
  that no text contains an em dash, and that every literal `t!("key")` used under `src/` exists.
  A missing key would otherwise render the key itself at runtime.

## Adding a string

1. Add the key with `en`, `es`, `gl` and `it` to the YAML file of its area.
2. Use `t!("area.key")` in the code. If the string is cached outside `render`, add it to the
   relevant `relocalize`.
3. Run `make test`: the completeness tests fail on a missing language, a placeholder mismatch or
   an unknown key.

## Adding a language

1. Add the code, native name and matching rules to `Language` in `state/locale.rs`.
2. Add the translation to every key of every YAML file. The completeness test lists what is
   missing.
3. Add the language to the Settings dropdown and extend the glossary below.
4. Check the longest labels at the default window width and at 1000 px (Spanish and Italian are
   the longest so far). Fix clipped text with an ellipsis or by allowing wrapping, never by
   shrinking the font.

## Glossary

Use these terms consistently. Postino is a developer tool: keep a neutral, short, professional
tone, and use the impersonal or infinitive form on buttons ("Guardar", "Gardar", "Salva"), not
the imperative with "tú" or "usted". Spanish is neutral (Spain and Latin America). Galician
follows the RAG normative.
