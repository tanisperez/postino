Postino 1.0.1 fixes problems found using 1.0.0 on Windows.

## What changes

### Changed

- **`postino` on the Windows PATH** (#284): the installer adds the install folder to your `PATH`, so `postino` works in any new terminal, and uninstalling removes it. The portable zip does not change the `PATH`.
- **Faster git diffs** (#285): opening the diff of a changed file runs about three git commands instead of two plus one or two per change block, since Postino works out which blocks are staged from the index itself. A file with many changes opens much sooner, most of all through WSL and with the git of Windows, where every git command costs more.
- **A larger minimum window size** (#291): the window can no longer be made smaller than 1024 × 640, below which the title bar, the request tabs and the diff header did not fit.
- **Faster git in WSL workspaces** (#286): every git command run inside WSL costs about 10 ms instead of about 40 ms. Opening the diff of a file with seven change blocks in a WSL workspace went from about 640 ms to about 100 ms.

### Fixed

- **Menus open on click** (#280): the environment selector, the method selector, the workspace switcher, the branch menu and every other drop-down menu opened as soon as the mouse button was pressed. They now open when it is released, like a click on a button.
- **The command line on Windows works like any other tool** (#282, #283, #281): `postino.exe` is now a console program. cmd and PowerShell wait for each command, so the prompt no longer comes back before the output and `%ERRORLEVEL%` or `$LASTEXITCODE` hold its exit code. The output can be redirected to a file or piped to another command, which also makes it reach CI runners and SSH sessions, where it was lost. From a WSL terminal the lines no longer drift to the right. Opening the window from a terminal still gives the prompt back at once, and on Windows 11 24H2 or later no console window appears when Postino starts from the Start menu (older versions show one for an instant).
- **The window no longer opens tiny on Windows** (#290): closing Postino while it was minimized saved a negative window size, and the next start opened the smallest window. Postino now keeps the last real size.
