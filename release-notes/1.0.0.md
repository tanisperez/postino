Postino 1.0.0 is the first stable version.

## What changes

### New

- **Command line mode** (#240): the same `postino` binary now works without the window, with no display needed, for CI pipelines and servers. `postino run` runs requests, folders or the whole workspace through the same steps as Send (OAuth 2.0, scripts and `test()`), with `--env`, `--var` and `--env-file` for the variables, `--bail` and `--filter`, and readable, JSON or JUnit output. `postino get`, `post`, `put`, `patch`, `delete`, `head`, `options` and `http <METHOD>` send a one-off request like curl, with headers, query parameters, JSON, raw or multipart bodies and Basic or Bearer authorization, and `-o` downloads the body to a file with a progress bar, like wget. `postino check` validates every request and environment file. The exit codes tell a passed run from a failed test, a network error or a broken file. See the new [Running in CI](https://postino.tanis.codes/docs/ci.html) guide.
- **Load tests from the command line** (#241): `postino load` runs a load test with the app's engine and options (`--vus`, `--duration`, `--ramp-up`, `--think`, `--no-keep-alive`, `--stop-on-error`). On a terminal a live dashboard shows the progress, throughput, errors, percentiles, a latency chart, the statuses and a table per request, with `q` to stop, `p` to pause and `s` to save a report; in CI it prints progress lines. `--fail-if 'p95>500ms'` conditions set the exit code, `--report` writes the same PDF, Markdown, JSON or CSV reports as the app, the run is saved to the history unless `--no-save`, and `--compare last` prints the changes against an earlier run.
- **Context menus from the keyboard** (#232): `Shift+F10`, or the menu key on Linux and Windows, opens the menu of the active tab under it, or, while the Environments panel is shown, the menu of the environment open in the active tab. The arrow keys, Enter and Esc work in it.

### Changed

- **Faster git for workspaces inside WSL** (#229): git commands no longer start `wsl.exe` each. Postino keeps one running and sends the commands to it, so only the first command waits for it to start. Set `TELAIO_GIT_WSL_SESSION=0` to go back to the old way.

- **New look for the dialogs** (#237): every dialog, from Settings to the confirmations, is a flat panel with a solid border, a short shadow and a darker backdrop. The header has no dividing line and shows an icon before the title, and the close button sits on a light background. A destructive confirmation shows a warning icon in red.
- **Keyboard hints in the command palette** (#237): a bar at the bottom shows the keys to move, open and close. The search field is larger.
- **Filter in the keyboard shortcuts cheat sheet** (#237): type part of an action or of its keys to list only the shortcuts that match. The keys are drawn as key caps, and the up and down arrows scroll the list.

### Fixed

- **Commit buttons of the same width** (#238): in Source Control, **Commit** and **Commit and Push…** now have the same width. They share the row when the panel is wide enough and stack, each at full width, when it is narrow, so the second label is never cut.
